# Solara · 아트 가이드

최신 사용자 지정 방향은 업로드한 레퍼런스의 **선명한 셀 셰이딩 기반 서브컬처 판타지 RPG**입니다. 이전 동화풍 혼합에서 맑은 청색·남색·금색, 정교한 애니메이션풍 얼굴·판타지 의상·빛 표현으로 전환했습니다. 이 디렉터리는 새로 제작한 원본과 아트 작업 기준을 보관합니다. 현재는 정적 일러스트·월드 오브젝트를 게임에 연결한 첫 제작 배치입니다. 방향별 걷기 프레임과 개별 노멀맵까지 완료한 것으로 보고하지 않습니다.

PNG4종은 요청 화풍과 독창적 캐릭터·소품 설명으로 OpenAI 이미지 생성 도구에서 제작했습니다. 캐릭터·월드 시트의 배경 제거도 같은 도구로 수행했습니다. 기존 게임 캐릭터나 외부 게임 리소스를 복사하지 않았습니다. 원본은 보존하고 브라우저에는 WebP만 제공합니다. 셸/속성/무기 아이콘은 프로젝트 내에서 작성한 SVG 경로입니다.

## 화풍과 배치

- 사파이어 하늘·투명한 청록 바다·아이보리 모래·선명한 초록 잔디와 청색 지붕, 얇고 또렷한 윤곽선·셀 음영·빛나는 금속 장식을 사용합니다. 종이/수채화 질감은 새 시트에서 제거했습니다. 캐릭터는 속성별 머리색·의상·장신구로 구분합니다.
- 메뉴·전투는 새 판타지 의상의8명 전신 일러스트를 사용하고 맵은 작은 여행자/주민 스프라이트를 사용합니다. 현재 여행자 아바타를 출전 캐릭터에 따라 바꾸는 기능은 없습니다.
- 지도와 장식은 서버 지형을 따릅니다. 아트 변경 때문에 충돌·상호작용 좌표·방문자 권한·보상·캐릭터 능력치를 바꾸지 않습니다. 쉼터 발밑은(1050,675), 야자수는 굽은 줄기 뿌리에 앵커를 맞춥니다. Y정렬과 그림자 설정을 유지합니다.
- 원래 해안 지형 이미지는 x1570에서 자르고 다리(y760~840)/안뜰을 기존 접근 판정과 맞춥니다. 지형 타일 경계는 샘플링 여백과 거울 반복으로 완화합니다.
- 고품질 지형은 새 디퓨즈 아트와 기존 높이 기반 노멀맵으로 실제 조명을 계산합니다. 캐릭터·건물은 현재 조명을 별도로 계산하지 않는 일러스트이고, 접촉 그림자는 별도 타원입니다. 정교한 투영 그림자나 모든 오브젝트 노멀맵이 완성된 것은 아닙니다.
- 야자수 흔들림·파도·입자·걷기 시 가벼운 상하 움직임은 움직임 감소 설정을 따릅니다. 현재 걷기는 좌우 반전/상하 움직임이며4방향 독립 프레임 애니메이션은 후속입니다.

## 내보내기

```bash
# 원본 아트 또는 아틀라스 프레임을 수정할 때만 필요합니다.
# Python3와 Pillow가 필요하며 일반 npm 설치/빌드/실행에는 필요하지 않습니다.
python3 scripts/export-art.py
npm run build
```

스크립트는 원본을 이동하거나 덮어쓰지 않고 WebP 인코딩과 프레임 메타데이터를 생성합니다. 투명 프레임 경계를 읽고 명목 격자 근처의 실제 투명 간격으로 행을 구분합니다. 지형 경계에는8px 여백을 두며 원본 그림은 재배치하지 않습니다. 다음 행의 모자 등이 위 프레임에 섞이지 않도록 인접 프레임 간 투명 여백도 검사합니다. 결과는 `client/public/art/*.webp`, Phaser용 `*.json`, React용 `client/src/art-manifest.ts`입니다. 세 파일 묶음의 프레임이 일치해야 합니다. `Art.tsx`는 명시적인SVG clipPath로 프레임 경계를 자릅니다. viewBox의 여백만으로는 가로로 긴 새 포즈에서 다른 행의 캐릭터가 비칠 수 있으므로 이 처리를 제거하지 않습니다. 변경 후 내보낸 파일도 함께 커밋합니다.

현재 브라우저 아트4종의 합계는1,666,030바이트(약1.59MiB)입니다. 미로그인 시작 화면은 키 비주얼382,044바이트를 사용하고, 로그인 후 맵/메뉴는 나머지3종을 사용합니다. 최초 다운로드 합계2MiB를 회귀 기준으로 사용하며 PNG 원본은 다운로드하지 않습니다. WebP는 캐릭터 메뉴와 전투에서 같은 URL을 공유하고 Phaser는 맵 시트를 한 번 읽습니다. 메모리/실기기 성능 인증 수치는 아닙니다.

## 확인과 다음 순서

아트 계약 테스트는 실사용 캐릭터/주민/적의 누락, 이미지 경계, Phaser/React 프레임 일치, WebP 형식과 다운로드 예산을 검사합니다. 새 PC/모바일 테스트는8명 실제 보유 캐릭터를 전환해 서로 다른 프레임을 확인하고 맵/뽑기/전투 아트·실제 도주 행동을 검증합니다. 기존 설정·움직임 감소·협동·탐험·상자·전투 회귀를 모두 유지합니다. 실제SVG를 캔버스로 렌더링해 여백의 이웃 프레임 노출이0인지 검사합니다. 새PC/모바일 시작 화면 테스트는 키 비주얼 디코딩·입력란 화면 내 배치·회원가입→로그아웃→재로그인을 실제로 확인합니다.

사용자가 정한 다음 순서는 **아트 마감 → 추가 콘텐츠 → 밸런스**입니다. 아트 단계의 잔여 작업은 방향별 걷기/동작 프레임, 캐릭터·건물별 노멀맵과 그림자, 전투 배경/기술·궁극기 연출, 실기기 화면·로딩 검수입니다. 이를 정리한 뒤 새 콘텐츠와 마지막 난도/경제 조정을 진행합니다. 기존 밸런스 보고서를 새 아트나 전체 콘텐츠의 완성 판정으로 사용하지 않습니다.
