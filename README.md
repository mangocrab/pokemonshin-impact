# 소라빛 여름 · Solara

브라우저용 2D 협동 RPG를 단계별로 개발하는 저장소입니다. 현재1~9단계와10단계의 설정·지형 조명·환경 애니메이션·소리·초기 최적화를 구현했습니다. 계정·개인 월드 탐험·최대4인 협동 전투·기술 학습·캐릭터 수집과 성장, 주민3명과5종의 부탁, 제단 퍼즐과 해금 지역, 전투 소모품과 협동전 재접속 복구, 안뜰의1인·협동 패턴 전투를 플레이할 수 있습니다. 최신 레퍼런스에 맞춘 셀 셰이딩 서브컬처풍 아트와 청색·금색 UI를 맵·전투·수집·시작 화면에 적용했습니다. 전체 요구사항 및 미구현 기능은 [개발 계약](docs/ROADMAP.md)을 참고하세요.

## 실행

Node.js 24, npm 11, Docker가 필요합니다. 현재 클라우드 체크아웃은 `/workspace/pokemonshin-impact`입니다.

```bash
bash scripts/install.sh
export DATABASE_URL=postgresql://resort:local-development-only@127.0.0.1:5432/resort
npm run dev
```

클라이언트 5173, 서버 3001, PostgreSQL은 루프백 5432를 사용합니다. DB 데이터는 `/workspace/.pokemonshin/postgres`에 보존합니다. 예시 DB 암호는 격리된 로컬 개발 전용입니다. 운영 DB에는 별도 자격 증명을 사용하세요. 웹 배포는 HTTPS 및 동일 출처 리버스 프록시가 필요합니다.

회원가입 후 해안을 방향키/WASD 또는 터치로 이동할 수 있습니다. 맵 안의 상자 3개에 가까이 다가가 E키 또는 상호작용 버튼으로 엽니다. 서버가 소유권과 거리(64px)를 검증합니다. 건물과 야자수는 통과할 수 없습니다. 위치는 2초마다 및 접속 종료 시 저장되며 재접속 시 복원됩니다. 페이지 새로고침 시 쿠키 세션으로 로그인 상태가 복원됩니다. 친구 및 멀티플레이 메뉴에서 친구 요청·초대·진입 신청으로 함께 탐험할 수 있습니다. 산호 집게게와1인 턴제 전투도 플레이할 수 있습니다. 친구를 모으면 협동 보스전도 플레이할 수 있습니다. 메뉴에서 뽑기·강화·인벤토리를 이용할 수 있습니다.

## 친구와 멀티플레이

1. 서로 다른 브라우저 프로필/시크릿 창에서 계정2개를 생성하고 로그인합니다.
2. `친구 및 멀티플레이`에서 상대의 정확한 계정 아이디로 친구 요청을 보냅니다. 상대는 화면의 요청 알림을 눌러 수락합니다.
3. 친구 목록에서 `내 월드에 초대`를 누르면 상대가 초대 수락 후 방문합니다. 또는 소유자가 `진입 신청 허용`으로 설정하면 다른 계정이 소유자 아이디로 신청할 수 있습니다.
4. 방문자는 캐릭터를 움직이며 함께 탐험합니다. 소유자 포함 최대4명, 계정의 여러 탭은1명입니다. 방문자는 상자를 열거나 자신의 월드 상자 API를 우회 호출할 수 없습니다.
5. 방문자는 메뉴에서 개인 월드로 복귀할 수 있습니다. 소유자가 마지막 탭을 닫거나 로그아웃/다른 월드 이동 시 방문자는 자동 복귀합니다. `멀티플레이 차단` 설정은 현재 방문자를 복귀시키고 대기 요청을 취소합니다.

초대·진입 신청은5분 동안 유효합니다. 친구 관계와 요청은DB에 보존하며 방문 목록은 단일 서버 프로세스 메모리에서 관리합니다. 일반 탐험은 서버 재시작 시 개인 월드로 재접속하며, 진행 중 협동전은 아래 복구 규칙을 따릅니다. 방문 중 이동은 개인 월드의 저장 위치를 덮어쓰지 않습니다. 1인 전투와2~4인 협동 보스전을 제공합니다. 전투는 개인 재화·아이템 보상을 지급합니다. 방문자도 주민과 대화할 수 있지만 월드의 부탁 수락·완료·보상 수령은 소유자만 가능합니다.

## 라운드 전투

1. `캐릭터` 메뉴에서 계정에 저장된 보유 동료와 최대4명 편성·기초 능력치·기술을 확인합니다.
2. 자신의 월드에 혼자 있을 때 시작 위치 왼쪽의 산호 집게게(740,560) 가까이에서 `산호 집게게와 전투`를 누릅니다.
3. 기술·아이템·방어·캐릭터 교체·도주 중 하나를 고릅니다. 서버가 적AI 행동도 선택하고 우선도와 스피드로 순서를 정해 각1회 행동합니다. 명중률80% 기술은 빗나갈 수 있습니다.
4. 교체는 행동을 소비합니다. 출전 캐릭터가 쓰러지면 생존한 대기 캐릭터를 선택해야 다음 라운드로 진행합니다. 전멸하면 패배합니다.
5. 새로고침·재접속 후에도 진행 중 전투를 복원합니다. 승리·패배·도주 후 탐험으로 돌아가며 새 전투는 전체 체력을 회복한 상태로 시작합니다.

현재 전투는 서버가 관리하는 기본1인 전투입니다. 속성·자속·상태이상·기술 패널티·패시브·궁극기를 제공합니다. 레벨 성장·기술 학습·승리 경험치 보상을 제공합니다. 재화/아이템 보상·돌파·무기 장착을 제공합니다. 협동 보스 승리도 개인 경험치를 지급합니다. 전투 중에는 서버에서 이동·상자·월드 입장을 제한합니다. 전투 상태와 행동 기록은PostgreSQL에 저장하며 재시도한 동일 버전 행동은409로 거절합니다. 구현은 `shared/combat.ts`, `server/src/combat/`, `client/src/Battle.tsx`에 있습니다.

## 전투 효과와 패널티

- 일반 기술은각4개, 패시브·궁극기는 별도입니다. 같은 속성 직접 공격은1.5배이며 기술 상세와 상성은 `shared/combat.ts`에서 관리합니다. 회복·보호막·상태 확률·지속 피해는 자속 보정을 받지 않습니다.
- 거센 파도 사용 후에는 다음 라운드의 모든 일반 행동이 제한됩니다. `행동 불가 · 다음 라운드`를 눌러 적 행동을 처리하면 그다음 라운드에 복귀합니다. 새로고침해도 패널티는 유지됩니다.
- 준비 기술은 한 행동을 준비에 사용한 뒤 `준비한 기술 발사`를 선택합니다. 행동 제한에 걸리면 준비가 취소됩니다. 반동·능력치 감소·재사용 대기시간·HP 사용 조건은 기술 설명과 버튼 제한으로 확인합니다.
- 화상·감전·빙결·둔화·속박·공격/방어/명중 감소가 기술에 명시된 경우에만 발생합니다. 상태 지속 라운드와 면역·해제는 서버에서 처리합니다. 빙결은 연장되지 않고 종료 후2라운드 면역입니다.
- 일반 기술 시도10, 방어15, 직접 피격10 에너지를 얻습니다.100에 도달하면 캐릭터 고유 궁극기를 선택할 수 있습니다. 사용 시100을 소비합니다.
- 확정된 서버 스냅샷의 순HP·보호막 변화, 상태이상 부여/해제와 교체를 전투 화면에 표시합니다. 궁극기가 실제 에너지를 소비하면 기존 일러스트와 속성별 색상의 컷인을 재생하며 다음 행동을 막지 않습니다. HP 표시는 라운드 전후의 합계 차이이며 개별 타격/치명타 수치가 아닙니다. 재접속·중복 응답으로 연출을 반복하지 않습니다. 계정/기기 움직임 줄이기에서는 정지된 결과 표시만 제공하고 저품질에서는 궁극기 초상화·광륜을 생략합니다.
- 이전 전투 스냅샷은 기존HP·라운드·장착 기술을 유지하며 새 필드를 초기화해 복원합니다. 시작4기술은 유지되며 새로 해금하는 기술과 장착4칸은 별도 저장합니다.

`npm run balance`는 서버 엔진으로 초기 밸런스를 탐색합니다. 기존 [결과](docs/BALANCE.md)는6단계 시작4캐릭터/Lv1의12,800회 기록입니다. 캐릭터 목록 확장 후 재실행 횟수는 달라질 수 있습니다. 실제 보스·4인 협동 테스트나 최종 밸런스 판정은 아닙니다.

## 성장과 기술 학습

- 승리하면 그 전투에 편성된 캐릭터당 경험치80을 받습니다. 도주/패배는 지급하지 않습니다. 전투 종료·행동 기록·경험치·해금·보상 고유키를 하나의DB 트랜잭션으로 처리하므로 재시도로 중복 지급되지 않습니다.
- 다음 레벨에 필요한 경험치는 현재 레벨×20입니다. 초기 상한Lv20에서 돌파로40/60/80까지 확장하며 초과 경험치는 다음 레벨 필요량까지만 보관합니다. 강화 메뉴에서 조개·여름 기록을 사용해 수동 성장할 수도 있습니다. 캐릭터마다 HP/공격/방어/스피드 성장 계수가 다릅니다.
- `캐릭터`에서 현재 레벨, 경험치, 기초 능력치, 장착4칸, 해금/미해금 기술과 요구 레벨을 확인합니다. 시작4기술을 보존하고 각 캐릭터에 총12개 기술 후보를 제공합니다. Lv30/40/50/60에는 선공 고위력·상태 제어·행동 제한 초고위력·준비/반동 기술을 해금합니다. 패시브·궁극기는 일반4칸과 별도입니다.
- 레벨 상승으로 새 기술이 해금되면 승리 결과와 알림에서 `새 기술 배우기`로 이동합니다. `나중에 배우기`는 장착 기술을 바꾸지 않으며 해금 기록을 보존합니다.
- `배우기` 후 장착4칸이 가득 찼으면 교체 대상과 전/후 결과를 확인하고 `교체 확인`을 눌러야 반영됩니다. 잊은 기술은 `다시 배우기`로 언제든 재습득합니다. 빈칸은 교체 없이 습득합니다.
- 서버는 보유 캐릭터/현재 레벨/해금 여부/일반 기술 목록/4칸/중복 기술/캐릭터 리비전을 검증합니다. 전투 중 변경은 차단하며 다음 전투는 실제 장착 기술과 성장 능력치를 사용합니다.

구현: `shared/progression.ts`, `server/src/training.ts`, `client/src/Training.tsx`. 마이그레이션은총14개이며 기존 계정은 첫 조회 시 기존 시작 기술을 유지한 채 해금·장착 기록을 초기화합니다. 데이터베이스를 리셋할 필요가 없습니다.

## 2~4인 협동 보스전

1. 다른 계정들을 자신의 월드로 초대하고 산호 집게게(740,560) 또는 해금된 안뜰 꽃등지기(1870,720) 근처64px 이내에2~4명이 모입니다. 소유자 화면의 `협동 보스전 모집` 또는 `안뜰 협동 보스전 모집`을 누릅니다. 단독일 때는 기존1인 전투 버튼이 유지됩니다.
2. 다른 참가자는 `협동 전투 참여`로 수락하거나 나가기로 거절합니다. 전원이 확인하면 선택한 위치의 산호 수호게 또는 안뜰 만개지기와 전투합니다. 모집 확인은60초 제한입니다.
3. 각 참가자는 자기 계정의 출전/대기 캐릭터와 기술만 조작합니다. 선택한 행동은 확정되며 다른 참가자에게 선택 내용은 공개하지 않습니다. 전원 선택 후 우선도·스피드·동률 규칙으로 한 번씩 행동합니다. 아군끼리 동률은 파티 표시 순서를 따릅니다.
4. 보스는 단일 대상 공격을 순환하고3라운드마다 광역 공격1회를 사용합니다. 보스HP/공격력은 시작 인원으로 정하며 이탈 후에는 줄이지 않습니다. 빙결 면역, 화상/감전 확률 저항을 가집니다.
5. 재충전/빙결로 행동 불가면 자동 대기합니다. 준비 기술·쿨다운·상태·강제 교체는 기존 규칙을 따릅니다. 전멸한 플레이어는 관전하지만 다른 생존 참가자는 진행합니다. 라운드60초가 지나면 미선택은 방어/대기, 강제 교체는 생존 캐릭터로 자동 처리합니다.
6. 승리 시 끝까지 남은 참가자마다 자신의 편성 캐릭터당 경험치120을 한 번 지급합니다. 방문자도 같은 개인 보상을 받으며 소유자의 상자/영구 진행도는 변경하지 않습니다. 전투·라운드 기록·개인 보상을 같은DB 트랜잭션에 저장합니다.
7. 명시적인 나가기·마지막 인증 세션 로그아웃은 즉시 이탈하며 이후 승리 보상은 없습니다. 소유자의 취소·로그아웃·멀티 차단은 전투를 취소합니다. 일시적인 마지막 소켓 종료에는30초 복구 유예를 적용합니다. 여러 탭 중 하나만 닫는 것은 계정 이탈이 아닙니다.

협동전은 단일 서버 프로세스에서30초 이내 재접속과 서버 재시작 후 복구를 지원합니다. 끊긴 참가자가 있으면 라운드와 시간 초과 처리를 일시정지하고 선택·HP·에너지·상태·쿨다운을 보존합니다. 방문자는 호스트가 접속해 있으면 자동 복귀합니다. 호스트 연결이 끊기면 방문자를 즉시 개인 월드로 안전 복귀시키고 전투를 예약해 둡니다. 호스트 복귀 후 방문자는 `협동 전투 복귀` 버튼으로 다시 합류합니다. 모두 복귀하거나 마지막 대기자가 이탈하면 다음 선택에60초를 새로 부여합니다.

방문자의 유예가 끝나면 해당 참가자만 이탈하고, 호스트의 유예가 끝나면 전투 전체를 취소합니다. 서버 재시작은 저장된 미완료 전투에 시작 시점부터30초 유예를 부여하며 기존 쿠키 인증과 참가자·월드 접근 권한을 다시 검사합니다. 선택만 한 아이템은 소비하지 않고 이미 커밋한 소비·라운드·보상을 다시 실행하지 않습니다. 유예 중 성장/장비/구매 잠금도 유지합니다. 이미 나갔거나 유예가 끝난 전투에 재입장하거나 무기한 오프라인으로 보존하는 기능과 다중 서버 운영은 지원하지 않습니다. 1인 전투 복원은 유지합니다.

구현은 `shared/coop.ts`, `server/src/combat/coop.ts`와 공통 `engine.ts`입니다. `npm run balance:coop`은2/3/4인4,800전투를 실행해 [초기 결과](docs/COOP_BALANCE.md)를 저장합니다. 현재 입문 보스 난도는 낮으며 최종 균형은 성장·장비·추가 캐릭터 후 재평가합니다.

## 화면·소리 설정과 초기 최적화

- `설정`에서 그래픽 품질, 동적 조명, 그림자, 환경 효과, 움직임 줄이기, 음소거와 음량을 계정별로 저장합니다. 기본 음소거, 음량40%입니다. 저장 즉시 적용하고 새로고침해도 유지하며 Phaser/소켓을 재생성하지 않습니다. 다른 탭의 변경과 충돌하면 덮어쓰지 않고 최신 설정을 불러올 수 있습니다. 설정 API는 인증·필드·범위를 검증하고DB 리비전으로 동시 쓰기를 보호합니다.
- 제작한 모래·잔디·얕은 물 디퓨즈와 높이 기반 노멀맵으로 Phaser4의 지형 이미지에 실제 픽셀 조명을 적용합니다. 파도선·야자수·환경 입자가 움직이고 접촉 그림자는 표시 여부를 선택합니다. 현재 조명은 지형에만 적용하며 그림자는 타원 형태의 표현입니다. 제작 일러스트를 아래 아트 확장에서 연결했으며 공통 여행자 아바타의4방향 걷기를 연결했으며 캐릭터/건물별 노멀맵·정교한 투영 그림자는 후속입니다.
- 낮음은 조명/환경 입자를 끄고 렌더링20FPS·배경 움직임10Hz로 제한합니다. 높음의 조명도 실제 사용 광원1개로 제한합니다. 높음은 최대30FPS입니다. 메뉴/전투 중 배경 애니메이션은 갱신하지 않습니다. 계정 또는 기기의 움직임 감소 설정은 파도·식물 애니메이션을 멈추고 입자를 숨깁니다. 이동 판정·전투 계산·보상은 그래픽 설정과 무관하게 계속 서버에서 수행합니다.
- Web Audio로 직접 합성한 파도 환경음과 상자·전투 효과음을 제공합니다. 음소거 해제 후 사용자 조작이 있어야 오디오를 만들고, 음소거/음량0/탭 숨김에서는 일시 정지합니다. Phaser 자체 오디오는 비활성화해 중복 컨텍스트를 피합니다. 계정 전환/로그아웃에는 오디오를 정리합니다. 음악과 전문 사운드 에셋은 포함하지 않습니다.
- Phaser는 로그인 후 동적으로 불러옵니다. 안뜰 전투 확장 후 프로덕션 빌드에서 초기JS는 약312KB(gzip100KB), 게임 청크는 약1,444KB(gzip390KB)입니다. 이전 단일JS 약1,713KB의 다운로드를 나눴으며 전체 코드량이 줄었다는 뜻은 아닙니다. 게임 청크의500KB 경고는 여전히 남습니다.
- 서버는 위치가 바뀌지 않는 입력에 자기 위치 확인만 응답하고 동일한 월드 참가자 목록은 재방송하지 않습니다. 이동 검증·권한·저장 방식은 유지합니다. 새로고침 후 전투가 먼저 복원되더라도 월드 준비가 끝나기 전에는 행동을 비활성화합니다.
- `npm run balance:growth`는 실제 저장 편성에 사용하는 공통 `loadoutStats`와1인/협동 엔진으로8캐릭터·Lv1/20/60·장비·상성/면역·기술 패널티를 탐색합니다. [보고서](docs/GROWTH_BALANCE.md)는28,800전투와60라운드 미종료159건을 기록합니다. 가상 성장 적을 사용하며 실제 맵 적을 바꾸지 않습니다. 최종 밸런스 검증은 아닙니다.

구현: `shared/settings.ts`, `shared/loadout.ts`, `server/src/settings.ts`, `client/src/Settings.tsx`, `client/src/CoastPresentation.ts`, `client/src/Sound.tsx`. 다음 작업은 추가 이야기·퍼즐·지역, 완성 아트와 실기기 성능 측정, 최종 난도·경제 조정입니다. 전체 게임 완성으로 간주하지 않습니다.

소프트웨어 WebGL 진단에서는4개 데스크톱 컨텍스트를 순차 생성할 때 각 월드 준비까지 약1.3/2.1/4.5/8.0초가 걸렸습니다. 이 수치는 이 클라우드의 진단값이며 실제 사용자 기기 성능을 보증하지 않습니다. 다중 브라우저 테스트의 초기 접속 대기는15초로 두고 기존 행동/권한 검증은 유지합니다.


## 주민과 해안의 부탁

1. 시작 지점 남쪽 산책길의 **다온(845,640)** 또는 쉼터 오른쪽 항구 길의 **모루(1210,700)** 가까이64px 안으로 이동합니다. `[E] … 대화` 버튼 또는 E키로 대화를 시작합니다. E키는 개봉 가능한 상자가 함께 가까우면 상자를 우선합니다. 대화 중에는 이 화면의 이동을 멈춥니다.
2. 다온에게 `여름의 첫 선물`을 받습니다. 자신의 월드 상자를1개 열고 돌아와 `보상 받기`를 누르면 소라160/조개500/여름 기록2개를 받습니다. 이전에 발견한 상자도 인정하므로 기존 계정을 다시 시작할 필요가 없습니다.

## 안뜰 협동 보스전

호스트가 물결의 안뜰을 해금하고 친구를 초대하면, 자신의 안뜰이 잠긴 방문자도 호스트의 열린 다리를 건너 함께 도전할 수 있습니다. (1870,720)의 꽃등지기 근처64px 안에 소유자 포함2~4명이 모인 뒤 `안뜰 협동 보스전 모집`을 누르고 각자 참여를 확인하세요. 소유자만 모집하며 서버는 호스트 월드의 현재DB 해금·실제 위치·접속 인원·전투 잠금을 검사합니다. 자기 지역 해금이나 좌표를 요청에 끼워 넣어 조건을 우회할 수 없습니다.

전원이 동의하면 **안뜰 만개지기**와 전투합니다. 시작 인원이2/3/4명이면 HP576/832/1088, 공격력44/49/55이며 이탈 후에는 줄이지 않습니다. 자연 속성, 빙결 면역, 화상/감전 확률25% 저항을 가집니다. 기존 꽃등지기의 순환 기술을 사용하고3라운드의 만개는 생존한 출전 캐릭터 모두에게 한 번의 광역 행동으로 피해를 줍니다. 사용 후 다음 라운드는 쉬며 이후 순환을 이어갑니다. 예고는 협동 화면에도 표시합니다. 전원 선택 전에는 진행하지 않고 휴식 패널티·지속 피해·라운드 종료를 참가자 수만큼 반복하지 않습니다.

기존60초 선택 제한과30초 연결 복구 유예, 호스트 단절 시 방문자 개인 월드 복귀 및 재합류를 그대로 사용합니다. 승리하면 끝까지 참여한 각 계정이 편성 캐릭터당120XP·소라40/조개500·기존 재료·과즙/소금을 받습니다. 호스트의 수락된 승리 부탁만 진행하고 방문자의 개인 월드 부탁·지역·상자는 변경하지 않습니다. 같은 전투의 재전송으로 중복 보상은 없으며 반복 도전은 새 전투로 시작합니다.

`shared/coop.ts`가 보스별 기본 능력치에서 인원 배율을 적용합니다. 기존 산호 수호게의 수치·패턴과 모든1인 전투는 유지합니다. 새 마이그레이션은 없고14개를 유지합니다. 단위3개와 실제4계정 DB/API1개가 배율·광역1행동·휴식1회·해금/거리/권한·선택 대기·재접속·개인 보상·월드 독립성을 확인합니다. PC/모바일2개는 실제 두 브라우저의 초대/모집/참여·방어·광역 예고·새로고침·승리를 검증하며, 접근 준비에는 서버 이동 검증을 통과하는 Socket.IO 입력을 사용합니다. 기존4브라우저 협동 회귀도 유지합니다. 최종 보스 난도·다중 서버·추가 콘텐츠는 후속입니다.


## 세린과 안뜰의 여름 기록

물결의 안뜰 남쪽 (1740,900)의 식물 기록가 **세린**에게 다가가 E키 또는 대화 버튼을 누르세요. 지도와 모험 일지에 위치를 표시합니다. 안뜰이 잠긴 월드에서는 세린과 상호작용할 수 없으며 서버가 현재 월드의DB 해금을 검사합니다. 방문자는 호스트의 열린 안뜰에서 이야기와 부탁 현황을 볼 수 있지만 수락·진행도 변경·보상 수령은 소유자만 할 수 있습니다.

- **안뜰의 잠든 노래**: ‘여름의 첫 선물’ 보상 수령과 안뜰 해금 후 수락합니다. 수락 이후 자기 월드의 꽃등지기 또는 협동 만개지기에게 승리하고 세린에게 돌아오면 소라240/조개900/여름 기록3개를 받습니다. 이전 승리와 해안 집게게·수호게 승리는 이 목표에 포함하지 않습니다. 협동은 호스트의 부탁만 진행하며 방문자의 정상 개인 전투 보상은 유지합니다.
- **꽃잎 사이의 여름 편지**: 잠든 노래의 보상을 받은 뒤 수락합니다. 안뜰의 오래된 선물을 발견하고 돌아오면 소라160/조개600/성장 결정3개를 받습니다. 이미 연 안뜰 선물은 수락 시 인정합니다. 원래 해안 상자3개는 이 목표에 포함하지 않으며, 안뜰 선물도 기존3상자 목표에는 포함하지 않습니다.

선행 조건·수락·목표·수령 상태는 기존 `WorldQuest`에 저장하고, 해금과 장착 기술처럼 목표 종류와 대상을 데이터로 구분합니다. 전투 목표는 서버의 실제 적ID, 상자 목표는 해당 부탁의 상자ID 목록을 사용합니다. 일반 승리 부탁과 원래 상자 목표는 유지합니다. 새 지역 해금 시 일지의 잠김 상태도 즉시 갱신합니다. 수락/보상은 명시적 선택이며 대화·일지 조회만으로 완료 처리하지 않습니다.

같은 부탁의 병렬 수락은 기록1개, 병렬 보상 요청은 지급1회이며 목표·보상·재화는 기존 트랜잭션과 조건부 갱신으로 보호합니다. 전투/원격/방문/위조 진행도·월드ID 우회는 차단합니다. 새로고침 후 단계와 보상 수령을 복원합니다. 신규 마이그레이션 없이 기존14개와 기존 계정 기록을 유지합니다.

단위4개는 주민 접근·선행 조건·대상 전투·상자 분리를 확인합니다. 실제 DB/API1개는 수락 전 안뜰 승리·다른 적 승리 미인정, 실제 대상 승리·안뜰 상자 개봉, 해금/거리/전투/방문자 검사, 병렬1회 보상·후속 조건·재접속을 확인합니다. 기존4계정 협동 검증에도 호스트의 대상 부탁 진행을 추가했습니다. PC/모바일2개는 세린 대화→수락→실제 승리→보상→이미 발견한 선물 인정→보상→재접속 일지를 확인하고, 기존 퍼즐 테스트는 해금 직후 새 부탁이 열리는지도 확인합니다. 새 이야기의 접근 이동은 실제 서버 검증을 통과하는 Socket.IO 입력입니다. 현재 주민3명·부탁5종의 기초 콘텐츠이며 장편 분기 서사·반복 의뢰·최종 경제/난도 조정은 남아 있습니다.
